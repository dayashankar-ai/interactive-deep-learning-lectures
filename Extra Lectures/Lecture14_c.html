What is Convolution?
The Mathematical Foundation
Intuitive Definition: Convolution is a mathematical operation that measures how much a small pattern (filter/kernel) matches different parts of a larger signal (image).
The Everyday Analogy: Imagine you have a template of a specific key shape, and you slide it across a wall of keys to find which keys match your template. Convolution does exactly this with visual patterns!
Mathematical Definition (1D):
(f * g)(t) = \int f(\tau) \times g(t - \tau) d\tau
In discrete form:
(f * g)[n] = \sum f[m] \times g[n - m]
For Images (2D Discrete Convolution):
(I * K)[i,j] = \sum_{m}\sum_{n} I[m,n] \times K[i-m, j-n]
Where:
  • I = Input image
  • K = Kernel/filter
  • * = Convolution operation
  • The result is a feature map
What This Means in Plain English:
  1. Take a small pattern (kernel)
  1. Slide it across the entire image
  1. At each position, multiply corresponding values and sum
  1. The result tells you how well the pattern matches at that location
The Step-by-Step Convolution Process
Breaking Down the Magic Into Simple Steps
Position the Kernel
Place the kernel at the starting position (typically top-left) of the image.
Image (5×5):          Kernel (3×3):
[1 2 3 4 5]           [1 0 -1]
[6 7 8 9 0]           [2 0 -2]
[1 2 3 4 5]     *     [1 0 -1]
[6 7 8 9 0]
[1 2 3 4 5]
Element-wise Multiplication
Multiply each kernel value with its corresponding image pixel.
Image patch:           Kernel:                Multiplication:
[1 2 3]               [1 0 -1]               [1×1  2×0  3×(-1)]
[6 7 8]      ×        [2 0 -2]      =        [6×2  7×0  8×(-2)]
[1 2 3]               [1 0 -1]               [1×1  2×0  3×(-1)]

Result:
[1   0   -3]
[12  0   -16]
[1   0   -3]
Sum All Products
Add up all the values from the element-wise multiplication.
Sum = 1 + 0 + (-3) + 12 + 0 + (-16) + 1 + 0 + (-3) = -8
Place Result in Output
Put the computed sum in the corresponding position of the output feature map.
Output[1,1] = -8
Slide and Repeat
Move the kernel one position (based on stride) and repeat all steps until the entire image is processed.
The Beautiful Result: Each output pixel represents how well the kernel pattern matches that location in the image!

Feature Maps
The Output of Convolution
What is a Feature Map?
A feature map is the result of applying a convolution filter to an image. It shows where and how strongly a particular feature appears.
Mathematical Relationship:
Input Image (H × W × D) * Filter (K × K × D) = Feature Map (H' × W' × 1)
Where:
  • H, W = Height, Width of input
  • D = Depth (channels) of input
  • K = Kernel size
  • H', W' = Output dimensions (depend on padding and stride)
Feature Map Interpretation:
  • High Values (bright): Strong feature presence
  • Low Values (dark): Weak feature presence
  • Zero Values: No feature detected
Example - Vertical Edge Detection:
Original: Photo of building with vertical columns
Feature Map: Bright lines where columns are, dark everywhere else
Multiple Feature Maps:
One Filter → One Feature Map
N Filters → N Feature Maps (each detecting different features)
Common in CNNs:
  • 32 filters → 32 feature maps
  • 64 filters → 64 feature maps
  • Each map specializes in different patterns
The Insight: Feature maps are like specialist reports - each one tells you about a specific type of pattern in the image!
Convolution Mathematics
The Detailed Formulation
2D Convolution Formula:
Feature\_Map[i,j] = \sum_{m=-k}^{k} \sum_{n=-k}^{k} Input[i+m, j+n] \times Kernel[m,n] + Bias
Where:
  • (i,j) = Position in output feature map
  • k = (kernel_size - 1) / 2
  • Bias = Optional constant added to result
Multi-Channel Convolution:
Feature\_Map[i,j] = \sum_{m=-k}^{k} \sum_{n=-k}^{k} \sum_{c=0}^{C-1} Input[i+m, j+n, c] \times Kernel[m,n,c] + Bias
For RGB images (3 channels)
Each filter has depth matching input depth!
Output Size Calculation:
Output\_Height = \frac{Input\_Height + 2 \times Padding - Kernel\_Height}{Stride} + 1Output\_Width = \frac{Input\_Width + 2 \times Padding - Kernel\_Width}{Stride} + 1
Example:
  • Input: 224×224, Kernel: 3×3, Stride: 1, Padding: 1
    Output: (224 + 2×1 - 3)/1 + 1 = 224×224 (same size!)
  • Input: 224×224, Kernel: 3×3, Stride: 2, Padding: 0
    Output: (224 + 0 - 3)/2 + 1 = 111×111 (half size!)
Computational Complexity:
Operations per convolution:
  • Multiplications: Kernel_Size² × Input_Channels × Output_Height × Output_Width
  • Total for all filters: Above × Number_of_Filters
Example (typical CNN layer):
Input: 224×224×3, 64 filters of 3×3
Operations: 9 × 3 × 224 × 224 × 64 ≈ 86 million operations!
Stride and Its Impact
Controlling Output Size
What is Stride?
Stride is the number of pixels the filter moves between each convolution operation.
1
Stride = 1 (Default)
  • Move filter one pixel at a time
  • Maximum overlap between operations
  • Preserves spatial resolution
  • Most detailed feature detection
2
Stride = 2 (Downsampling)
  • Move filter two pixels at a time
  • Less overlap between operations
  • Reduces spatial resolution by ~half
  • Faster computation, less memory
Mathematical Impact:
  • Stride = 1: Input 100×100 → Output ~100×100 (same size)
  • Stride = 2: Input 100×100 → Output ~50×50 (half size)
  • Stride = 3: Input 100×100 → Output ~33×33 (third size)
Real-World Applications:
Stride = 1: Feature extraction layers
  • Detailed analysis needed
  • Preserve spatial information
  • Used in early CNN layers
Stride = 2: Downsampling layers
  • Reduce computational cost
  • Focus on larger-scale features
  • Common in pooling alternatives
The Trade-off: Larger stride = faster computation but less detailed analysis!
Padding
Preserving Information at Borders
The Border Problem:
Original Image (5×5):      After 3×3 Convolution:
[a b c d e]                [result only 3×3]
[f g h i j]                Border information lost!
[k l m n o]
[p q r s t]
[u v w x y]
Padding Calculation for "Same" Output:
Padding = \frac{Kernel\_size - 1}{2}
  • For 3×3 kernel: Padding = (3-1)/2 = 1 pixel
  • For 5×5 kernel: Padding = (5-1)/2 = 2 pixels
  • For 7×7 kernel: Padding = (7-1)/2 = 3 pixels
When to Use Which:
  • Valid: When edge information is not crucial
  • Same: When preserving spatial dimensions is important
  • Full: Rarely used, mainly for specific signal processing tasks
Types of Padding:
Valid Padding (No Padding)
  • Don't add any pixels
  • Output size: (Input_size - Kernel_size + 1)
  • Information at borders is lost
  • Faster computation
Example: Input: 5×5, Kernel: 3×3
Output: 3×3
Same Padding
  • Add zeros around border to preserve size
  • Output size: Same as input size
  • Preserves border information
  • More computation required
Original:        Padded:
[a b c]         [0 0 0 0 0]
[d e f]   →     [0 a b c 0]
[g h i]         [0 d e f 0]
                [0 g h i 0]
                [0 0 0 0 0]
Full Padding
  • Maximum padding possible
  • Output size larger than input
  • Captures all possible convolution positions

Convolution vs Cross-Correlation
The Technical Distinction
True Mathematical Convolution:
(f * g)[n] = \sum f[m] \times g[n - m]
Cross-Correlation (What's Actually Used in Deep Learning):
(f \star g)[n] = \sum f[m] \times g[n + m]
The Key Difference:
Convolution: Flips the kernel before sliding
Cross-correlation: Uses kernel as-is
Convolution requires:        Cross-correlation uses:
[1  0 -1]                    [1  0 -1]
[2  0 -2]        →           [2  0 -2]
[1  0 -1]                    [1  0 -1]
(flipped)                    (original)
Why Deep Learning Uses Cross-Correlation:
  1. Learning adjusts for any flipping - the network learns optimal filter values regardless
  1. Computationally simpler - no need to flip kernels
  1. Intuitive implementation - sliding the filter "as designed"
  1. Historical naming - early papers called it convolution, name stuck
Practical Impact:
  • For hand-designed filters: Difference matters
  • For learned filters: Network adapts, difference irrelevant
  • Most deep learning frameworks implement cross-correlation but call it "convolution" for historical reasons
Visual Comparison:
True Convolution:
Kernel → Flipped Kernel → Apply
[1 0] → [0 1] → [Cross-correlate with flipped]
[0 1] → [1 0]
Cross-Correlation:
Kernel → Apply Directly
[1 0] → [Use as-is]
[0 1]
Bottom Line: When we say "convolution" in deep learning, we usually mean cross-correlation, and that's perfectly fine!
Kernel Size Trade-offs
Small vs Large Receptive Fields
Receptive Field: The area of the input image that influences a single output pixel.
Small Kernels (3×3, 5×5)
Advantages
  • ✅ Fewer parameters (faster training)
  • ✅ Less computational cost
  • ✅ Better gradient flow in deep networks
  • ✅ More nonlinear transformations possible
Disadvantages
  • ❌ Small receptive field (local features only)
  • ❌ Need more layers for global understanding
  • ❌ May miss large-scale patterns
Parameter Count Example:
  • 3×3 kernel with 64 filters: 3×3×64 = 576 parameters
  • 7×7 kernel with 64 filters: 7×7×64 = 3,136 parameters (5.4× more parameters!)
Large Kernels (7×7, 11×11, 15×15)
Advantages
  • ✅ Large receptive field (captures global context)
  • ✅ Can detect large-scale features directly
  • ✅ Fewer layers needed for global understanding
Disadvantages
  • ❌ Many more parameters (slower training)
  • ❌ Higher computational cost
  • ❌ Poorer gradient flow in deep networks
  • ❌ More prone to overfitting
Modern Approach - Stacking Small Kernels:
  • Two 3×3 convolutions = 7×7 receptive field
  • Three 3×3 convolutions = 11×11 receptive field
Benefits:
  • Fewer parameters than single large kernel
  • More nonlinear activations
  • Better gradient flow
When to Use Which:
  • Small (3×3): Most hidden layers, detailed feature extraction
  • Medium (5×5): Intermediate layers, moderate-scale features
  • Large (7×7+): First layer only (raw pixel processing)

Separable Convolutions
Efficient Computation Strategies
The Efficiency Challenge:
Standard convolution is computationally expensive. Can we achieve similar results with fewer operations?
Depthwise Separable Convolution:
Split convolution into two steps:
  1. Depthwise Convolution: Apply separate filter to each input channel
  1. Pointwise Convolution: Combine results with 1×1 convolution
Standard Convolution:
Input: H×W×C_in
Filter: K×K×C_in×C_out
Operations: H×W×K×K×C_in×C_out
Example:
Input: 224×224×3
Filter: 3×3×3×64
Operations: 224×224×3×3×3×64 = 86M operations
Depthwise Separable Alternative:
Step 1 - Depthwise:
Input: H×W×C_in
Filter: K×K×1×C_in (separate filter per channel)
Operations: H×W×K×K×C_in
Example: 224×224×3×3×3 = 1.4M operations
Step 2 - Pointwise:
Input: H×W×C_in
Filter: 1×1×C_in×C_out
Operations: H×W×1×1×C_in×C_out
Example: 224×224×1×1×3×64 = 9.6M operations
Total Separable Operations: 1.4M + 9.6M = 11M operations
Speedup: 86M / 11M = 7.8× faster!
When Separable Works Well:
  • Mobile applications (limited computation)
  • Real-time processing requirements
  • Large-scale deployment scenarios
Trade-offs
  • ✅ Much faster computation
  • ✅ Fewer parameters
  • ✅ Less memory usage
  • ❌ Slightly reduced representational power
  • ❌ May need more layers to compensate

Convolution Implementation
From Theory to Code
Naive Implementation (Educational):
def convolution_2d(image, kernel):
    # Get dimensions
    img_h, img_w = image.shape
    ker_h, ker_w = kernel.shape
    
    # Calculate output size
    out_h = img_h - ker_h + 1
    out_w = img_w - ker_w + 1
    
    # Initialize output
    output = np.zeros((out_h, out_w))
    
    # Perform convolution
    for i in range(out_h):
        for j in range(out_w):
            # Extract patch
            patch = image[i:i+ker_h, j:j+ker_w]
            # Element-wise multiply and sum
            output[i, j] = np.sum(patch * kernel)
            
    return output
Optimized Implementation Strategies:
1. Vectorized Operations:
# Use numpy broadcasting for efficiency
def fast_convolution(image, kernel):
    # Create sliding windows using stride_tricks
    windows = sliding_window_view(image, kernel.shape)
    # Vectorized multiplication and sum
    return np.tensordot(windows, kernel, 
                        axes=((2,3),(0,1)))
2. FFT-based Convolution:
# For large kernels, use frequency domain
def fft_convolution(image, kernel):
    # Pad to avoid circular convolution
    padded_size = np.array(image.shape) + 
                  np.array(kernel.shape) - 1
    
    # Transform to frequency domain
    image_fft = np.fft.fft2(image, padded_size)
    kernel_fft = np.fft.fft2(kernel, padded_size)
    
    # Multiply in frequency domain
    result_fft = image_fft * kernel_fft
    
    # Transform back
    result = np.fft.ifft2(result_fft)
    return np.real(result)

Advanced Convolution Variants
Modern Innovations
Grouped Convolution
Idea: Split channels into groups, apply separate convolutions
Benefits: Reduces parameters, enables parallel processing
Standard: Input(256) → Conv → Output(512)
Parameters: 3×3×256×512 = 1.2M
Grouped (4 groups): Input(256) → 4 parallel Conv → Output(512)
Parameters: 4×(3×3×64×128) = 0.3M (4× reduction!)
Transposed Convolution (Deconvolution)
Idea: "Reverse" convolution for upsampling
Use case: Semantic segmentation, image generation
Regular Conv: 224×224 → 112×112 (downsampling)
Transposed Conv: 112×112 → 224×224 (upsampling)
Mathematical relationship:
If forward conv: y = Conv(x, W)
Then transposed: x' = Conv_transpose(y, W^T)
1×1 Convolution (Pointwise)
Purpose: Channel-wise mixing without spatial mixing
Applications:
  • Dimension reduction/expansion
  • Cross-channel information mixing
  • Cheap computational building block
Example:
